## 1. 连接时自动应用网络配置

### 当前原因

`AppModel.startSession()` 只调用 helper 的 `startSession`；配置 IP 的 `applyNetworkConfiguration()` 是另一个用户操作。因此“数据通道已建立”与“已配置上网地址”分离。

尤其注意：`TetherKitSession.start()` 是非阻塞的。调用返回只代表请求被受理，不能立即假定虚拟网卡已就绪并下发 DHCP。

### 目标行为与建议

- 一次点击完成：受理连接 → USB/RNDIS 就绪 → 虚拟网卡就绪 → 应用 DHCP 或保存的静态配置 → 回读实际地址、网关和 DNS。
- 默认 DHCP；连接使用一份固定的配置快照，避免连接期间修改表单影响在途操作。
- 建议由 helper 负责这次连接的完整编排，使关闭 App 窗口不会使流程半途停止。具体接口设计以最小必要改动为准。
- 等待就绪必须有界，遇到失败、断开或手机拔出及时结束；旧连接的迟到回调不能配置下一次连接的新接口。
- DHCP 失败时保留明确状态和“重试获取地址”入口，不要求用户先断开再连接，也不要无限自动重试。
- 配置只能作用于当前会话实际拥有的系统侧网卡。不能把客户端任意传入的接口名当成可操作目标。
- 沿用用户选择的默认路由策略，不为了“连通”自动关闭 Wi-Fi/VPN 或强制抢占全局默认路由。

### 验收

- [x] 默认设置下，点一次连接即可获取手机网段的地址，无需另点“应用”。
- [ ] 保存的有效静态配置可在下次连接时自动应用。
- [ ] 握手慢、DHCP 超时、连接中拔出手机、连续点击和重新连接不会错配网卡或重复执行。
- [ ] 连接流程中关闭主窗口仍能完成配置；已建立的连接继续由 helper 保持。

## 2. 显示连接阶段与准确的失败原因

### 目标行为

- 主窗口显示“正在连接手机”“正在获取 IP”“网络已就绪”等有实际意义的阶段。
- “网络已就绪”表示数据通道与所选地址配置就绪，**不等于已验证公网可达**。地址、网关、DNS 显示真实回读值，缺失项不能伪造成功。
- 握手失败、手机断开、地址配置失败分别提示；获取地址失败提供针对该步骤的重试入口。
- “测试网络”按钮继续按需检测网关、DNS、常用网站；不在后台周期性访问网站，也不把公网检测强制加入每次连接。
- 网络测试结果应与对应会话绑定，避免上一次连接的结果在新连接里被当成当前结果。

### 验收

- [x] 已建数据通道但尚未拿到 IP 时，不显示让人误以为已能上网的成功状态。
- [ ] 失败信息说明具体阶段，并提供适用的重试操作。
- [ ] 中英文文案完整；关闭窗口后没有新增持续 UI 轮询，详情图表和日志仍只在详情窗口打开时运行。

## 3. 可信 App 日常连接免管理员密码

### 当前原因

当前每次特权操作都复核 `system.privilege.admin`。App 缓存的令牌只有约 5 分钟有效，App 重启也会失去缓存。helper 虽已是 root，仍需要确认是谁在请求操作。

现有 XPC listener 接受所有连接，安全边界依赖每次方法调用的授权凭据。**不能仅删除授权检查来实现免密码。**

### 建议方案与必须验证的边界

- 安装或更新特权组件时经管理员授权，建立本机可信 App 与允许使用它的本机用户记录；普通连接、断开、重试地址配置不再要求管理员密码。
- helper 从真实 XPC 连接身份核验调用方用户和运行代码身份，不能相信客户端自己上报的 UID、路径、应用名、bundle ID 或哈希。
- 当前使用本地临时签名，可研究在授权安装时登记该构建的代码签名哈希，并在连接时校验。此方案尚未实现和验证，后续 AI 需确认临时签名、运行代码及依赖加载条件下的实际安全边界，再落地。
- 信任记录仅允许 root 写入；更新信任也必须经过授权流程。新编译的 App 哈希改变时，清楚提示需要重新授权更新信任。
- 运行权限只覆盖 TetherKit 当前会话和自有网卡；安装、卸载、更新 helper 等管理动作继续要求管理员授权。
- 缺失、损坏或不匹配的信任记录不能静默放行。保留明确的授权恢复入口，兼容首次使用和旧 helper 升级。
- 不缓存管理员密码，不修改系统通用管理员权限的规则。延长现有令牌期限只能算临时减少弹框，不能作为这一项完成的依据。

### 验收

- [ ] 授权建立信任后，等待超过 5 分钟、重启 App、重插手机再连接，普通操作均无需管理员密码。
- [ ] 未登记程序、不同用户、伪造 bundle ID 或路径的程序不能获得运行权限。
- [ ] 新构建身份变化后要求重新授权；授权更新成功后恢复正常使用。
- [ ] 不能通过接口参数修改其他网卡或越权操作其他会话。
- [ ] 安装、卸载、信任更新仍经过管理员授权；失败和用户取消不会留下部分可用的错误信任记录。

## 4. 网络配置移入高级设置，并保存成功配置

### 目标行为

- 主界面以连接、状态和“测试网络”为主；DHCP/静态 IP、DNS、默认路由策略等放入可展开或单独的高级设置。
- 首次使用默认 DHCP。持久保存上一次成功应用的网络配置，重启 App、断开再连接后自动恢复使用。
- 表单草稿与已保存配置分开：校验失败或应用失败时，不能覆盖已保存的有效配置。
- 未连接时允许编辑配置并供下一次连接使用；在线修改配置时保留“应用”操作，只有存在待生效改动时才需要它。
- 明确提示静态地址来自之前的网络配置，允许方便地切回 DHCP。无需新增按手机分组、多套配置管理等未要求功能。
- “撤销配置”是一次性动作，不把它保存为后续默认连接模式。

### 验收

- [x] 普通 DHCP 使用不需要进入高级设置。
- [ ] 重启 App 后可恢复上次成功配置；错误草稿不会覆盖它。
- [ ] 在线修改后能明确区分待应用内容与实际回读状态。
- [x] 撤销配置后重连不会永久停留在“不配置网络”的状态。
